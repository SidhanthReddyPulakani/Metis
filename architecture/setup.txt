Yep. Let's set up **Metis as a deployable monorepo from day one**, rather than building locally and figuring out deployment later.

I recommend **Docker-first development**. The same containers we run locally can later be deployed to a cloud VM/container platform.

## 1. Project structure

```text
metis/
├── apps/
│   ├── web/                 # Next.js
│   └── api/                 # FastAPI
│
├── workers/
│   └── ingestion/           # ingestion worker
│
├── packages/
│   └── shared/              # shared schemas/contracts
│
├── infrastructure/
│   ├── docker/
│   └── nginx/
│
├── tests/
│   ├── integration/
│   └── e2e/
│
├── docker-compose.yml
├── docker-compose.prod.yml
├── .env.example
├── .gitignore
├── README.md
└── Makefile
```

I'd keep **frontend, API, and workers separate** even though we're starting small. This maps directly to the architecture we're planning.

- **Git**


# 7. Infrastructure

Our initial `docker-compose.yml` should contain:

```text
web
api
worker
postgres
redis
minio
```

The important thing is that **the application services are stateless**.

Postgres stores metadata.

MinIO stores datasets.

Redis handles jobs.

That means later we can deploy the same architecture to AWS/GCP/Azure without rewriting the application.

---

# 8. Environment variables

Create:

```text
.env.example
```

Something like:

```env
# Database
POSTGRES_USER=metis
POSTGRES_PASSWORD=change-me
POSTGRES_DB=metis
DATABASE_URL=postgresql+psycopg://metis:change-me@postgres:5432/metis

# Redis
REDIS_URL=redis://redis:6379/0

# Object storage
S3_ENDPOINT=http://minio:9000
S3_ACCESS_KEY=metis
S3_SECRET_KEY=change-me
S3_BUCKET=metis-datasets

# Application
ENVIRONMENT=development
SECRET_KEY=change-me
```

Then:

```bash
cp .env.example .env
```

Never commit `.env`.

## Deployment

For the first deployment, I would **not bother with Kubernetes**.

A perfectly respectable architecture is:

```text
                    Internet
                       │
                       ▼
                  Reverse Proxy
                       │
          ┌────────────┴────────────┐
          ▼                         ▼
       Next.js                   FastAPI
                                    │
                      ┌─────────────┼─────────────┐
                      ▼             ▼             ▼
                  PostgreSQL      Redis         S3
                                    │
                                    ▼
                                  Worker
```

You can deploy that on a cloud VM initially, then migrate individual components to managed services as Metis grows.

That gives us a **real deployable product without prematurely building enterprise infrastructure**.

---

### What I'd do next

Don't start writing ingestion yet.

First get the repository + Docker Compose + **Next.js ↔ FastAPI ↔ PostgreSQL ↔ Redis ↔ MinIO** skeleton working.

Once that's alive, we can build our **first real vertical slice**:

> **Upload CSV → direct upload to object storage → create ingestion job → worker processes it → stream progress to UI → persist ingestion results.**

That will establish the foundation for virtually everything else in Metis.
